# Amendment 002 — unquantized BF16 MLX generation

## Decision

Formal generation uses `mlx-lm==0.31.2` on Apple Silicon with locally converted,
unquantized BF16 weights from the pinned Hugging Face revisions. The converted model
directory has a manifest containing the source revision, dtype, backend version,
quantization flag, every file hash, and one artifact digest stored in each generation
record. Exact JSON structure is enforced by the separately pinned XGrammar backend;
see Amendment 003.

Some model repositories publish both Transformers shards and an equivalent
`consolidated.safetensors` export. Conversion downloads the Transformers shards and
ignores that duplicate export; the selected files remain pinned by the same source
revision, and every converted file is hashed.

## Reason

The initially tested PyTorch/MPS path was impractically slow for the preregistered
matrix. MLX executes the same pinned model weights and BF16 arithmetic without
quantization and supports deterministic fixed-batch sampling on the available M4 Pro.
This is an execution-backend change made before formal generation and before held-out
judgments are unsealed; it does not change model identity, prompts, decoding settings,
draw count, parsing, failure policy, retrievers, methods, or evaluation.

## Compatibility gate

Before formal generation, eight sorted SciFact queries are generated with three draws
each. A second independent run must exactly reproduce raw outputs and all draw-level
metadata except creation timestamps. Any model conversion, BF16, memory, or exact
reconstruction failure stops the formal run. Quantization is not an allowed fallback.
