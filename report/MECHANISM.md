# DESA 机制诊断

本报告使用已经冻结的七个数据集、三次生成结果和完整排名，不重新生成参考文本，也不改变主实验。Dense-only 与 Sparse-only 分别隔离两个通道算子；相关性和分箱分析均为事后描述，不用于选择阈值或构造自适应规则。

## 主要发现

1. **Dense 扩展是保守的，但角度不是收益旋钮。** 七个数据集等权平均的查询偏转角为 11.98°，单次观测最大为 27.87°，全部满足 45° 上界。偏转角与 Dense-only 的 nDCG 变化和深度变化几乎不相关（等权平均 Spearman ρ 分别为 0.010 和 0.011）。残差构造限制了语义漂移，但不能仅凭角度判断一次扩展是否有效。

2. **Sparse 锚定确实大幅重排头部。** 原查询排名与锚定排名的 Top-20 平均更换 26.15%，相关文档的倒数排名变化在七个数据集上均为正。相关文档倒数排名增益与 Sparse-only 的 nDCG 增益呈中等正相关（ρ=0.391），而单纯的 Top-20 更换比例与 nDCG 增益只有弱相关（ρ=0.078）。关键不是改变多少文档，而是是否把相关文档推向前部。

3. **机制强度与访问深度不是单调关系。** Dense 角度四分位和 Sparse 更换比例四分位都没有形成单调的质量或访问曲线。因此，这组结果不支持基于单一角度或更换率设置阈值，也不支持据此增加自适应超参数。

4. **两个算子需要联合评价。** Dense-only 的等权平均 nDCG 提高 0.0049，但 Dense 深度平均增加 6.05%；Sparse-only 的 nDCG 提高 0.0142，Sparse 深度平均降低 3.19%，但在 Touché-2020 上仍会变深。主方法的质量—访问改善不能简化成“任一单通道算子越强越好”。

## Sparse 支持集审计

在非负加性词项评分的理想条件下，扩展查询包含原查询词项，因此分数锚定应保留原查询支持集。六个数据集的导出排名完全满足这一性质。Touché-2020 的 147 个查询—生成组合中有 23 个组合缺失了 1–2 个极低分尾部文档，共 25 次；最差支持保留率为 99.9988%，平均保留率为 99.9999%。复查发现原查询词项仍包含在扩展查询中，异常发生在 Lucene 全排名导出的极低分尾部，而不是头部排序。

因此，论文可以保留带前提的数学性质，但实验部分应如实报告这一实现边界，不把实际 Lucene 导出描述为七个数据集上的绝对支持集相等。

## 论文放置建议

- 正文：用一张紧凑图展示 Dense 偏转角和 Sparse Top-20 更换比例，说明两个算子在真实查询上的作用方式不同。
- 附录：放四分位曲线、相关系数表和 Touché-2020 支持集审计。
- 不采用：根据 Dense 角度或 Sparse 更换率设计自适应开关；当前数据不支持这种单调叙事。
